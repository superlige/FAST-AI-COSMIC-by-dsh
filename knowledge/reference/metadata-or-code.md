# 配置和代码的分工

苍穹的一个业务功能由元数据配置和插件代码合起来实现。配置由平台自己执行、在开发平台里看得见改得了、不用编译部署；
插件是配置表达不了时的补充。定实现方式时按下面的顺序过一遍，前一层能做的不往后推。

## 各层配置各管什么

| 要的效果 | 用什么 | 怎么查、怎么写 |
|---|---|---|
| 固定的默认值、必录、长度精度；按**单据状态**（新增、修改、已提交、已审核……）显隐和锁定 | 字段和控件自己的属性 | [metadata-form.md](metadata-form.md) |
| 满足某个条件时才必录 | 字段的必录条件 | `MustInputProbe` 读，[metadata-form.md](metadata-form.md) 的 `set` 写 |
| 按**字段的值**显示、隐藏、锁定、解锁字段或整块容器，改字段和分录行的样式 | 界面规则 | [metadata-form-rules.md](metadata-form-rules.md) |
| 一个字段变了，另一个字段跟着算、跟着带值、跟着清空 | 业务规则 | [metadata-business-rules.md](metadata-business-rules.md) |
| 保存、提交、审核这类操作执行时不满足条件就拦下并提示 | 操作上的校验 | [metadata-entity.md](metadata-entity.md) 的 `OpMetaProbe` 读，[metadata-form.md](metadata-form.md) 的 `add check` 写 |
| 下推时目标单的字段从源单取值、按条件取值、用公式算 | 转换规则的字段映射 | [metadata-botp.md](metadata-botp.md)、[metadata-botp-write.md](metadata-botp-write.md) |

## 字段和控件自己的属性

不随数据变的行为直接写在属性上，不需要规则也不需要代码：字段的默认值、必录、长度和精度、下拉项、基础资料的过滤条件；
控件的可见性和锁定性，两样都按单据状态分别设（「已审核后只读」「只在查看时显示」就是这一层）。
能设哪些属性以 `FormLayoutProbe` 的 `LAYOUT_PROPS` 查到的为准。

必录有两档：`MustInput` 是始终必录；字段上再配一个必录条件（`MustInputCondition`），就变成条件成立时才必录。
必录条件是一段本单字段的表达式加一句说明，能取基础资料的属性，例如 `demo_org.number = '04'`、`demo_jylx.number='JYLX_01'`；
分录也能配「至少一行」的必录和它的条件。「类型选了外委，外委单位必填」是这一层，不用界面规则也不用校验插件。
一张单上现有的必录和必录条件用 `MustInputProbe`（`META_ENTITY=<实体>`）看。
两样都用布局写探针写，和别的改动放在同一份清单里：

```text
set demo_wwdw.MustInput=true                          # 始终必录
set demo_wwdw.MustInputCondition=demo_type = 'B'      # 条件成立时才必录（同时设成必录）；留空是去掉条件
```

## 界面规则

条件是字段值的表达式（`and` / `or`、比较、函数），真假两个分支各挂一组动作。动作只有这几类：
显示 / 隐藏、锁定 / 解锁（作用在字段上，或面板、字段组、分录这类容器上），字段格式和分录行样式。
「类型选了外委才显示外委信息那一块」「数量为 0 的行标红」属于这一层。

界面规则不改字段的值，不管必录（那是字段的必录条件），也不拦操作（那是操作上的校验）。动作的完整目录和条件函数目录由平台给，用 `meta formula form --actions` 和 `meta formula form --q` 查，
目录里没有的效果界面规则做不了。

## 业务规则

挂在实体（表头或某个分录）上，触发字段变化时按条件执行，界面录入和程序赋值都会触发。平台提供的动作：

- 公式计算：`金额 = ROUND(数量 * 单价, 2)` 这类字段间的算式；
- 携带基础资料属性：选了物料，把物料的规格、分组带到单据字段上；
- 字段值映射：一个字段的值原样给另一个字段；
- 清除字段值；
- 单位数量换算。

表达式能用的函数查 `meta formula biz`；写之前用试算、写之后用 `run rule biz` 看一组输入下算出什么。
业务规则只在这一张单据的字段之间算，取不到别的单据的数据。

## 操作上的校验

每个操作（保存、提交、审核、删除、自定义操作）上可以挂一组校验，操作执行时由平台在服务端逐条跑，不通过就拦下并给出提示；
界面上点按钮、列表上批量操作、程序调操作都经过它。平台提供的校验类型：

| 类型 | 做什么 | 要配的 |
|---|---|---|
| 合法性校验（`ConditionValidation`） | 用表达式判断数据合不合法，自己写提示 | 作用在表头还是哪个分录、表达式、表达式为真时报错还是为假时报错（`TrueThrow`）、提示文字 |
| 字段值合规性校验（`MustInputValidation`） | 按字段设计检查必录、数值范围、文本长度 | 三项各自可以跳过 |
| 组合字段唯一性校验（`GrpfieldsuniqueValidation`） | 几个字段的组合值不许重复 | 字段清单、空值查不查、提示文字 |
| 文本格式检查（`RegexValidation`） | 文本字段按指定格式或正则检查 | 字段清单、格式或正则、空值是否跳过、提示文字 |
| 单据在流程中校验 | 单据有流程在处理中就拦下 | 无 |
| 引用操作校验器（`RefOtherOpValidation`） | 把另一个操作的校验拿来一起跑，例如提交时跑保存的校验 | 被引用的操作 |

每条校验还能带一个前置条件（表达式）：条件成立这条校验才生效，同一个操作上按组织、按单据类型分开校验就靠它。例：

```text
合法性校验  表达式 demo_sampleconfirm = '0'  为真时报错  提示「样品符合确认为否，不允许提交。」
            前置条件 org.number = '0101' or org.number = '02'
```

表达式和业务规则用同一份函数目录（`meta formula biz`），只看得到这张单自己的字段和它引用的基础资料属性。
「数量必须大于 0」「结束日期不能早于开始日期」「编码加批号不能重复」「手机号格式」都在这一层，不写校验器插件。
要查别的单据、要逐行和别的行比、提示里要带算出来的数，才写校验器（见 [plugin-operation.md](plugin-operation.md)）。

一个操作上现有的校验用 `OpMetaProbe`（`OP_ENTITY=<实体> OP_FOCUS=<操作>`）看；跑一遍看拦不拦用 `run op`。
合法性校验用布局写探针加，`pass` 是表达式成立才放行、不成立就拦下，`fail` 是表达式成立就拦下：

```text
add check submit pass demo_qty > 0 ;; 数量必须大于 0
add check audit fail demo_sampleconfirm = '0' ;; 样品符合确认为否，不允许审核。 ;; when org.number = '02'
remove check submit <校验 id>
```

一条合法性校验只能用表头和一个分录的字段，用到分录字段时逐行算。表达式写进去之前会核语法、函数和字段。
其余几种类型（组合字段唯一性、文本格式、引用操作）把操作、类型和要配的内容列给用户在开发平台的操作设置里配。

## 转换规则

下推时目标单每个字段的值由转换规则的字段映射决定，一条映射是一个目标字段加它的取值方式：
取源单的某个字段、公式（表达式跑在目标单上下文）、按条件取不同的值。源单哪些数据能下推由规则的数据范围条件定，
映射之后还要再算的由规则里的业务规则定。

转换插件是最后一层：只有取值要查第三张单、要调服务、或者要按映射表达不了的算法拆行并行时才用。
源单字段原样给目标字段、套一个公式就能得出的值，都配成映射，不写进转换插件。
已有的映射和插件用 `BotpRuleProbe` 看，映射的写入见 [metadata-botp-write.md](metadata-botp-write.md)。

## 配置表达不了的才写插件

落到代码上的是这些：

- 要查别的单据或基础资料的数据来判断、取值（配置只看得到本单字段和源单字段）；
- 操作执行时的校验要查库、要跨行比较，或者操作要在同一个事务里连带写别的单据；
- 调平台服务、外部接口，发消息；
- 弹子页面、页面之间回传数据、按钮点下去的交互流程；
- 逐行、跨行的算法：按分录汇总后回写表头、行之间互相校验这类公式写不出的。

一个功能里常常两种都有：把配置能做的那部分配掉，插件只留配置做不了的那一段。
已经有插件的单据上加功能也一样，不因为「反正有插件」就把能配的写进代码。

## 字段只加用得上的

字段是持久的：加了就在业务表上多一列，退回元数据后列和数据还留着，一张表的列数和行宽都有上限。

- 每个新字段都要说得出谁写它、谁读它（哪条规则、哪条映射、哪段代码、界面上给谁看）。说不出的不加。
- 先看单据上有没有现成的字段能用（`MetaProbe` 查实体字段），含义相同就复用。
- 只在一次操作里用一下的中间值放在代码的变量里；能从已有字段随时算出来的值不另存一份，除非要按它查询、排序或留痕。
- 先把需求的主流程做通，再按实际需要补字段；为「以后可能用到」预留的字段不加。
